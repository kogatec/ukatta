# 学習サイクルの設計 — 週次テストと日次ドリル

> DESIGN.md §2.2（デイリーループ）・§5（模試生成）・§7（復習ループ）を、
> **「週1回の本番形式テスト」を軸とした週次サイクル**として再設計する。

---

## 0. サイクルの全体像

```
        ┌─────────────────────────────────────────────┐
        │                                             │
   ┌────▼─────────┐                                   │
   │ 週次テスト    │  志望校の本番形式・本番時間        │
   │ （土 or 日）  │  本番と同じ大問構成・配点・制限時間 │
   └────┬─────────┘                                   │
        │ 提出                                        │
   ┌────▼─────────┐                                   │
   │ 採点・分析    │  全問マーク式のため即時採点        │
   │              │  習熟度更新・合格率更新            │
   └────┬─────────┘                                   │
        │                                             │
   ┌────▼─────────┐                                   │
   │ 翌週の課題    │  重点単元 3〜5個を決定             │
   │ （週の目標）  │  「次のテストで取れる」が成功条件  │
   └────┬─────────┘                                   │
        │                                             │
   ┌────▼─────────────────────────────────┐           │
   │ 月〜金 日次ミッション（10〜30分）      │           │
   │  ・苦手中心、ただし全科目バランス      │           │
   │  ・マーク/数値マークで即時採点         │──────────┘
   │  ・毎日の結果が習熟度に反映される      │
   └───────────────────────────────────────┘
```

**設計の中心にある考え方**

週次テストは「実力を測る場」、日次ドリルは「実力を上げる場」。この2つを役割で明確に分ける。
測定と訓練を混ぜると、どちらも中途半端になる。

## 1. 出題形式 — マーク式の本番を再現する

**出題は全てマーク式（5択・数値マーク）に限定する。** 記述・証明・英作文は扱わない。
形式の詳細仕様は [question-format.md](question-format.md) を参照。

週次テストと日次ドリルは**形式では分かれない。分かれるのは「測定条件」である。**

| | 週次テスト | 日次ドリル |
|---|---|---|
| 頻度 | 週1回 | 毎日 |
| 形式 | 5択・数値マーク | 5択・数値マーク（同じ） |
| 構成 | **志望校の本番と同じ大問構成・配点・制限時間で通し** | 単元を絞った短時間演習 |
| 出題範囲 | 生徒には**事前に知らされない** | 「今日は二次関数」と分かっている |
| 採点 | 決定論的・即時 | 決定論的・即時 |
| 習熟度への重み | **大**（本番に近い条件での結果） | 中 |

**全問マーク式にしたことで、採点は週次・日次ともに完全に決定論的になる。**
AI採点は存在せず、採点待ちもコストも発生しない。DESIGN.md §5.3 が挙げる最大リスク
（問題品質の保証）も、「別モデルに3回解かせて一致を見る」検証が全問に適用できる。

### 1.1 週次テストと日次ドリルの本質的な違い

形式が同じでも、この2つは違うものを測っている。

- **日次ドリル**は「何の単元か分かっている状態」で解く。解法の見当がついている
- **週次テスト**は「何が出るか分からない状態」で、本番の時間制約の中で通しで解く

ドリルで解けてもテストで解けないのは極めてよくある。**この差こそが実力の差**であり、
形式を揃えたことで、その差を純粋に「条件の違い」として観測できるようになった（§5 の条件重み）。

### 1.2 対応できる入試形式 — 明示すべき制約

| 志望校の入試方式 | 対応 |
|---|---|
| 共通テスト・共テ利用 | **完全に再現できる**（5択 + 数値マーク） |
| 私大マーク型 | **完全に再現できる** |
| 公立高校入試 | 短答部分は数値マークで再現できる。**記述・証明・作文は対象外** |
| 国公立二次 | **対象外**（記述中心のため） |
| 難関私立・国立高校（記述型） | **対象外** |

**この制約はLP・オンボーディング・志望校登録時に明示する。**
国公立二次を第一志望とする生徒に「志望校の傾向を再現した模試」と謳うのは誤認を招く。
「共通テスト対策として使う」という位置づけを、登録時点で正しく伝える。

## 2. 週次テストの設計

### 2.1 実施タイミング

- **曜日と開始時刻はユーザーが設定**（既定は土曜または日曜）。部活・塾があるため固定は破綻する
- 前日夜と当日朝に通知（DESIGN.md §12 の通知エンジンに種別を追加）
- 開始後は本番同様にタイマーを走らせる。中断は許容するが、経過時間は止めない
  （「本番形式」である以上、時間の制約込みで測らなければ意味がない）

### 2.2 規模 — 学年と残り日数で変える

本番形式をそのまま毎週やると、高1で3時間、高3で5時間かかる。これは確実に離脱する。
**DESIGN.md の「学年は残り日数を決める鍵」という思想に沿って、規模を4段階に分ける。**

| 段階 | 条件（入試までの日数） | 週次テストの規模 | 日次ミッション |
|---|---|---|---|
| ライト | 365日超 | 1科目・30分・大問2題相当 | 10分 |
| スタンダード | 365〜180日 | 1〜2科目・各45〜60分 | 15分 |
| 強化 | 180〜90日 | 2科目・本番同形式で各60〜90分 | 20分 |
| 直前 | 90日以内 | 本番同一構成。**月1回は全科目通しの本番シミュレーション** | 25〜30分 |

「本番と同じ形式」は守りつつ、「本番と同じ量」は直前期にだけ課す。

### 2.3 科目ローテーション

毎週全科目は不可能。かといって弱点科目だけ回すと、他科目が静かに腐る。

**選択スコア**で決める。

```
選択スコア = 経過週数 × w₁ + 弱点度 × w₂ + 志望校での配点比率 × w₃
```

- 上位から、その週の実施時間に収まるまで科目を選ぶ
- **ハードガード: 4週間受験していない科目は無条件で選出**（取りこぼしの防止）
- 結果として、弱点科目は2週に1回、得意科目は3〜4週に1回のペースになる

### 2.4 未受験だった週の扱い

**責めない。** これは離脱防止の要である（DESIGN.md §12.2 の「煽らない・責めない」と同じ原則）。

| 状況 | 対応 |
|---|---|
| 1週スキップ | 前週の分析をそのまま継続。翌週に自動繰り越し |
| 2週連続スキップ | 短縮版（20分・1科目）を提案。「まずはこれだけ」と提示する |
| 3週連続スキップ | 週次テストの提案を止め、日次ミッションのみに切り替える。復帰を待つ |

未受験の事実は保護者レポートに**書かない**（DESIGN.md §11.5 と同じ理由。監視ツールにしない）。

## 3. 分析 — テスト結果を翌週の課題に変換する

### 3.1 分析の出力

週次テスト提出後、以下を生成する。

```
週次レポート
├ スコア
│   ├ 素点 / 志望校配点への換算点
│   ├ 前回テストとの差分
│   └ 合格率の更新
├ 単元別
│   ├ 習熟度が上がった単元（成果として明示する）
│   └ 習熟度が下がった／低いままの単元
├ 誤答タイプの分布（計算ミス何%、知識欠落何% …）
└ 翌週の重点単元 3〜5個 + 各単元の目標習熟度
```

### 3.2 重点単元の選び方

DESIGN.md §6.1 の優先度スコアをそのまま使う。

```
優先度 = (1 - 習熟度) × 志望校での出題頻度 × 配点
```

**「苦手 × 出やすい × 配点が高い」順**。苦手でも出ない単元を潰しても点は上がらない。

選ぶのは **3〜5個**。多いと散って、どれも終わらない。1日あたり1〜2単元に触れる分量に収まる。

### 3.3 成功条件を明示する

各重点単元に「**次のテストでこの単元が出たら取れる状態**（習熟度 0.8）」という
到達目標を置き、達成度バーで見せる。

これにより **「今週やったこと」と「来週測られること」が一本の線でつながる**。
これがこのアプリの学習ループの核心であり、汎用の問題集アプリとの差になる。

### 3.4 週の途中で達成したら

習熟度 0.8 に到達した単元は「クリア」として表示し（達成感を出す）、
配分を減らして**次点の単元を繰り上げる**。週の残りが無駄にならない。

## 4. 日次ミッションの設計 — 苦手中心、ただしバランスよく

### 4.1 「バランス」の定義

ここが設計上いちばん重要な判断になる。

**バランス = 全科目均等ではない。「志望校の配点比率」に対する最適配分である。**

英語200点・数学100点の大学を受けるなら、英語に多く時間を割くのが正しい。
均等配分は、一見公平だが得点を最大化しない。

```
科目 s への目標配分 = normalize( 配点比率ₛ × (1 + λ × 弱点度ₛ) )

λ = 弱点への傾斜係数
    1.0 … 既定
    1.5 … 「弱点強化モード」をユーザーが選んだ場合
    0.5 … 直前期（弱点を掘るより全体の維持を優先する時期）
```

配点比率を土台に、弱点度で傾ける。これで「苦手を主に、でも偏らない」が定量化できる。

### 4.2 出題の3層構成

1日の出題を3つの目的に分けて配分する。

| 層 | 目的 | 既定の配分 |
|---|---|---|
| **復習期限** | 忘却の防止（FSRS で `due_at <= 今日`） | 40% |
| **今週の重点** | 週次テストで見つかった弱点の克服 | 40% |
| **維持** | 得意科目の劣化防止 | 20% |

- 復習期限のタスクが無い日は、その分を「今週の重点」に寄せる
- 「維持」を切らないことが重要。得意科目は放置すると落ちるが、
  落ちたことに気づくのが週次テストの時点になり、手遅れになりやすい

### 4.3 バランスのハードガード

比率計算だけだと、丸め誤差や優先度の偏りで特定科目が長期間ゼロになりうる。
**制約として明示的に持つ。**

- 1日の出題は**最低2科目**にまたがる（総量が5問未満の日を除く）
- どの受験科目も**4日以上連続で0問にしない**
- 週単位で見て、各科目の実績配分が目標配分の **±50% 以内**に収まる

累積の乖離が大きい科目から優先的に埋めることで、日々の丸め誤差を吸収する。

### 4.4 分量

DESIGN.md §7.3 の「推定10〜20分」を、§2.2 の4段階に対応させて 10〜30分に拡張する。
朝の通知で「今日は12分で終わります」と所要時間を提示する方針は維持する。

## 5. 習熟度更新への影響 — 測定条件で重みを変える

これは細かいが、放置すると診断が静かに歪む論点である。

**日次ドリルは「何の単元か分かっている状態」で解く。週次テストは「何が出るか分からない状態」で解く。**
同じ正答でも、意味する実力が違う。ドリルで解けてもテストで解けないのは、極めてよくある。

DESIGN.md §6.1 の重み `w = 難易度重み × 新しさ重み` に、**条件重み**を掛ける。

| 測定条件 | 条件重み | 理由 |
|---|---|---|
| 週次テスト（本番形式・時間制限・通し） | **1.5** | 本番に最も近い条件。最も信頼できる |
| 日次ドリル | 1.0 | 基準 |
| 復習セッション（解説を見た直後の再テスト） | 0.5 | 短期記憶が効いており、実力を過大評価しやすい |

**形式を揃えたことで、この条件重みの意味が明確になった。** 週次と日次で出題形式が同じである以上、
両者の正答率の差は「形式の違い」では説明できず、純粋に測定条件（範囲を知っているか、
時間制約があるか、通しで解いているか）の差として解釈できる。

なお `question-format.md` §6 のまぐれ当たり補正は形式ごとに効き方が違う。
5択は推測確率 c = 0.2、数値マークは c ≒ 0 として扱う。

## 6. 画面設計への追加

DESIGN.md §3 の画面一覧に以下を加える。

| 画面 | パス | 内容 |
|---|---|---|
| 今週の目標 | `/weekly` | 重点単元3〜5個と達成度バー、次のテストまでの残り日数 |

**ホーム画面（`/`）の構成を改める。**

```
受験まで残り ◯日
────────────────
今日のミッション（推定15分）      ← 最も大きく、1つだけ
────────────────
今週の目標  ▓▓▓▓▓░░░  2/4単元クリア
次の週次テスト  あと3日・数学60分
```

DESIGN.md §3 の指針「ホームは今なにをやればいいか1つに絞る」は維持する。
週次の情報は**進捗の文脈**として下に置き、行動の選択肢を増やさない。

## 8. 保護者レポートへの反映

DESIGN.md §11 の日次レポートに加え、**週次テストの直後に週次サマリを送る**。
日次より週次の方が、保護者にとって意味のある単位である。

- 週次テストの結果（点数と前回差）、伸びた単元、今週取り組むこと
- **他の生徒との比較・順位は書かない**（DESIGN.md §11.4 の制約は維持）
- 未受験の週は、その事実を書かず、日次の積み上げのみを報告する

## 9. データモデルへの影響（概略）

実装時に詳細化する。ここでは必要な構造だけ示す。

- `mock_exams` に **種別**を追加（`weekly` / `monthly_full` / `adhoc`）。
  週次テストは模試の一種として扱えるため、テーブルを分けない
- **週次計画**（週の期間、重点単元3〜5個、各単元の目標習熟度と達成状況）
- **日次ミッション**（その日の出題セット。朝の通知で所要時間を提示する以上、事前生成が必要）
- **科目ローテーション状態**（科目ごとの最終受験週、次回選出スコア）
- `attempts` に**測定条件**（§5 の条件重みの根拠）
- ユーザー設定に**週次テストの曜日・開始時刻**

## 10. 主要なリスクと対応

| リスク | 対応 |
|---|---|
| **週次テストが重すぎて離脱する**（最大のリスク） | §2.2 の段階別規模、§2.3 の科目ローテーション、§2.4 の未受験を責めない設計 |
| **記述型入試の志望者が「傾向を再現できる」と誤解する** | §1.2 の対応範囲をLP・オンボーディング・志望校登録時に明示する。記述型が第一志望なら「共通テスト対策として使う」位置づけを登録時に伝える |
| 週次テストに出ない単元が放置される | §2.3 の4週ハードガードで全科目が必ず一巡する |
| 「バランス」が形骸化して特定科目に偏る | §4.3 のハードガードを制約として実装する（比率計算だけに頼らない） |
| ドリルの成績で実力を過大評価する | §5 の条件重みで、測定条件ごとに信頼度を変える |

## 11. 未確定事項

1. **週次テストの実施を促す強度**: 未受験時にどこまで働きかけるか。強すぎると義務感で離脱し、
   弱すぎるとサイクルが回らない。初期は弱めに設定し、継続率のデータを見て調整する
2. **記述型入試の志望者をどう扱うか**: 国公立二次・記述型高校入試が第一志望の生徒に対し、
   登録を断るのか、「共通テスト・併願私大の対策として使う」と位置づけて受け入れるのか。
   後者が現実的だが、その場合の期待値の伝え方（LP・オンボーディングの文言）を詰める必要がある
3. **公立高校入試の短答の再現度**: 短答（答えのみを書く形式）は数値マークで概ね再現できるが、
   都道府県によって記述の比率が大きく異なる。対応可能な都道府県を明示すべきか

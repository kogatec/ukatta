# 出題形式の設計

> DESIGN.md §5（模試生成パイプライン）・§6（苦手洗い出しエンジン）の詳細設計。
> **配信する問題はすべてマーク式に限定する。**
> 週次テスト・日次ドリルともにこの形式を使う（→ [learning-cycle.md](learning-cycle.md)）。

---

## 0. 決定事項

| 科目 | 形式 | 理由 |
|------|--------|------|
| 数学 | `numeric`（数値マーク） | 逆算を封じられる。共通テストの形式そのもの。複数正解事故が原理的に起きない |
| 英語 | `mark`（5択） | 共通テスト英語は全問マーク。誤答選択肢に読解の罠を仕込める |
| 国語 | `mark`（5択） | 現代文は伝統的に5択 |
| 理科・社会 | `mark`（5択） | 同上 |

`short` / `essay` / `proof` はスキーマ上は残すが、**生成も配信もしない**。
CHECK 制約 `deliverable_requires_auto_gradable_format` により、
記述系が誤って配信されることは DB レベルで防いでいる。

### この決定が引き受けるトレードオフ

**記述・証明・英作文は扱えない。** したがって国公立二次や記述型の高校入試は、
形式を再現できない。対応できる入試方式の一覧と、それをどこで明示するかは
[learning-cycle.md](learning-cycle.md) §1.2 に定める。

一方この制約は、DESIGN.md §5.3 が挙げる最大リスク（問題品質の保証）を大きく下げる。
記述式では「別モデルに解かせて一致を見る」検証が成立しにくいが、マーク式なら厳密な一致判定ができる。
**採点にAIを使わないため、採点待ちもコストも発生せず、採点結果がブレることもない。**

## 1. 中核となる設計思想 — 誤答は捨てずに診断に使う

マーク式の弱点は「過程が見えない」ことだが、**誤答の選択肢・誤答の数値そのものを設計すれば、過程は推定できる**。

生成時に、正答だけでなく **「典型的な誤り方」と、その誤り方をしたときに現れる値** をセットで作る。生徒がその値を選んだ／入力した瞬間に、誤答タイプが確定する。

```
従来: 誤答 → AIに解答内容を渡して分類 → error_type
本設計: 誤答 → 事前に紐づけた error_tag を引くだけ → error_type
```

これにより DESIGN.md §6.1 の「軸2: 誤答タイプ分類」が、**AI呼び出しなしで決定論的に**行える。コストが下がるだけでなく、分類がブレない。`root_skill_id`（真に欠けている前提スキル）も選択肢に事前に埋め込める。

AIによる分類は、**どの誤答パターンにも一致しなかった場合のフォールバック**としてのみ使う。

## 2. `mark` 形式（5択）の仕様

### 2.1 choices の構造

```jsonc
{
  "options": [
    {
      "key": "a",                       // 表示位置とは独立した安定ID
      "text": "筆者は制度の見直しが急務だと述べている",
      "correct": true
    },
    {
      "key": "b",
      "text": "地方自治体の事例が全国に広がりつつある",
      "correct": false,
      "error_tag": "example_as_claim",   // §4 の誤答タグ
      "root_skill_id": "uuid|null",      // 遡って復習すべき前提スキル
      "why_ja": "本文中の具体例を、筆者の主張そのものと取り違えています"
    }
    // ... 計5つ、正答はちょうど1つ
  ]
}
```

**制約（DBレベルで強制）**
- `options` はちょうど5要素
- `correct: true` はちょうど1つ
- 誤答4つはすべて `error_tag` を持つ
- `key` は5つとも相異なる

### 2.2 表示順のシャッフル

AIは正答を特定の位置に置く癖がある（生成モデルによって偏りが出る）。そこで:

- `questions.choices` には **論理的な順序で保存**（`key` が同一性を担保）
- 模試組版時に `mock_exam_items.choice_order`（`text[]`）へシャッフル済みの `key` 配列を記録
- 表示・自動保存・再開・結果表示のすべてでこの順序を使う

模試ごとに順序が固定されるため、途中保存や復帰で選択がずれる事故を防げる。

### 2.3 選択肢の均質性

正答だけが長い・正答だけが具体的、といった手がかり（テストワイズネス）を排除する。品質ゲートで機械的に検査する（§5）。

## 3. `numeric` 形式（数値マーク）の仕様

共通テスト数学の「アイウエに 0〜9 を入れる」形式。

### 3.1 answer の構造

```jsonc
{
  "type": "numeric",
  "slots": [
    { "label": "アイ", "value": "-1", "kind": "integer" },
    { "label": "ウ/エ", "value": "3/4", "kind": "fraction" }
  ]
}
```

- `kind`: `integer` | `fraction` | `decimal`
- 採点は**スロット単位**。部分点を出せる（`points` をスロット数で按分）
- 照合前に正規化する: 全角→半角、空白除去、`分数は既約形に統一`、`-0` → `0`

### 3.2 誤答値マッピング（`distractors`）

```jsonc
[
  {
    "slot": "アイ",
    "value": "-4",
    "error_tag": "sign_error",
    "root_skill_id": "uuid|null",
    "why_ja": "平方完成のときに定数項の符号を誤っています"
  },
  {
    "slot": "アイ",
    "value": "3",
    "error_tag": "case_omission",
    "why_ja": "定義域の端 x=0 だけを見て、頂点を確認していません"
  }
]
```

生徒の入力がこのいずれかに一致すれば、5択と同じ精度で誤答タイプが確定する。一致しなければ `error_tag = null` とし、AI分類のフォールバックに回す。

### 3.3 なぜ数学は5択にしないのか

| | 5択 | 数値マーク |
|---|---|---|
| 逆算（選択肢を代入して解く） | **できてしまう** | 不可能 |
| 複数正解が混入する事故 | 起こりうる（最大の事故要因） | 原理的に起きない |
| まぐれ当たり | 20% | ほぼ0% |
| 誤答からの診断 | 選択肢に紐づけ | 誤答値マッピングで同等 |
| 共通テストの再現性 | 低い | **そのもの** |

診断能力を落とさずに、事故要因と推測当たりを同時に消せる。

## 4. 誤答タグの体系

2階層にする。生徒に見せるのは細分類、習熟度エンジンが使うのは §6.1 の6分類。

`error_tags` テーブルで管理し、コードにハードコードしない（タグの追加でデプロイが要らない）。

### 数学

| tag | error_type | 表示名 |
|---|---|---|
| `sign_error` | calculation | 符号ミス |
| `arithmetic` | calculation | 計算間違い |
| `unit_error` | calculation | 単位・桁の誤り |
| `formula_confusion` | knowledge_gap | 公式の取り違え |
| `formula_unknown` | knowledge_gap | 公式・定理を覚えていない |
| `case_omission` | procedure | 場合分けの見落とし |
| `domain_ignored` | procedure | 定義域・条件の無視 |
| `partial_stop` | procedure | 途中の値で止めた |
| `wrong_target` | misread | 問われているものの取り違え |

### 英語

| tag | error_type | 表示名 |
|---|---|---|
| `example_as_claim` | misread | 具体例を筆者の主張と取り違え |
| `concession_misread` | misread | 譲歩構文（though / while）の読み落とし |
| `overgeneralization` | misread | 過度の一般化 |
| `outside_knowledge` | misread | 本文に根拠のない常識判断 |

## 5. 品質ゲートの追加要件

DESIGN.md §5.3 の検証に、形式別の項目を足す。

### `mark` 形式

1. **正答の一致**: 別セッションで3回独立に解かせ、3回とも同じ `key` を選ぶ
2. **誤答の否定検証（最重要）**: 4つの誤答選択肢を**1つずつ個別に**「これは確実に誤りか」と判定させる。1つでも「正しい／正しい可能性がある」と判定されたら**破棄**
   - AI生成マーク問題の最大の事故は「正解が2つある」こと。ここを通さない限り配信しない
3. **均質性検査**: 選択肢の文字数の最大／最小が2.0倍を超えない、正答だけが数値・他が文字列といった形式の不一致がない
4. **誤答タグの網羅**: 誤答4つがすべて相異なる `error_tag` を持つ（同じ誤りを4回書かせない）

### `numeric` 形式

1. **正答の一致**: 3回独立に解かせ、全スロットが一致
2. **誤答値の非衝突**: `distractors` の各値が正答と一致しないこと（自明だが生成バグで起こる）
3. **正規化後の一意性**: 誤答値どうしが正規化後に衝突しないこと

---

## 6. まぐれ当たりの補正 — 習熟度推定を壊さないために

### 6.1 問題

5択では、何も分かっていない生徒でも 20% 正解する。DESIGN.md §6.1 のベータ分布更新（正答 α+=w / 誤答 β+=w）をそのまま適用すると、**知識ゼロの生徒の `mastery` が 0 ではなく 0.2 付近に収束する**。弱点ランキングが静かに歪み、「苦手なのに苦手と表示されない単元」が生まれる。

### 6.2 補正モデル

生徒は確率 θ で「本当に理解していて正答」、確率 (1-θ) で「理解しておらず、確率 c でまぐれ当たり」とする。

```
P(正答)        = θ + (1-θ)·c
P(理解 | 正答) = θ / (θ + (1-θ)·c)
```

θ には現在の推定値 `mastery` を用いる。更新は:

```
正答時:  α += w · P(理解|正答)
        β += w · (1 - P(理解|正答))     ← まぐれ当たり分は「理解していない証拠」として計上
誤答時:  β += w
```

**例（c = 0.2）**

| 現在の mastery | 正答時の α 加算率 |
|---|---|
| 0.8 | 0.95 |
| 0.5 | 0.83 |
| 0.1 | 0.36 ← 弱い生徒の正答は大きく割り引かれる |

`numeric` 形式は c ≒ 0 のため、この補正は実質かからない（数学が数値マークである副次的な利点）。

**理論的な確認**: 真の実力が 0 の生徒（常にまぐれ当たりのみ）の不動点を解くと、補正ありでは `mastery → 0`、補正なしでは `mastery → c` になる。真の実力が 1 の生徒はどちらも `mastery → 1`。両端が正しく、推定量として素直に振る舞う。

**収束の実測**（真の実力 0 の生徒、5択、c=0.2、`src/lib/mastery.test.mts` で検証）

| 解答数 | 補正あり | 補正なし |
|---|---|---|
| 100 | 0.093 | 0.167 |
| 400 | 0.066 | 0.189 |
| 1600 | 0.049 | 0.195 |

`alpha` が単調増加しかしないため 0 への接近は緩やかだが、補正なしのように `c` に張り付くことはない。弱点ランキングは相対順序で決まるため、この収束速度で実用上の問題はない。

### 6.3 確信度による c の調整

DESIGN.md にある `self_confidence`（1〜4）で c を動かす。「自信がない」と申告した上での正解は、まぐれである確率が高い。

| self_confidence | c |
|---|---|
| 1（まったく自信がない） | 0.80 |
| 2 | 0.50 |
| 3 | 0.30 |
| 4（確信がある） | 0.20（＝素の推測確率） |

未申告時は 0.20。

### 6.4 誤概念の検出

**誤答 × 高確信（3以上）** は、単なる知識不足ではなく「間違って覚えている」状態であり、最も危険で、かつ最も放置されやすい。

- β の加算を 1.5 倍にする
- 復習キューに `state = 'relearning'` で最優先投入する
- 苦手分析画面で「思い込みの可能性」として別枠表示する

## 7. 出題形式の割り当てルール

ブループリント生成（DESIGN.md §5.1）時に、科目と入試方式から形式を決める。

```
数学 × (共通テスト | 共テ利用)     → numeric
数学 × 私大マーク                  → numeric（逆算防止を優先）
数学 × 二次記述                    → numeric で代用し、UIに「本番は記述式」と明示
英語・国語・理科・社会             → mark
高校受験 数学                      → numeric
高校受験 その他                    → mark
```
